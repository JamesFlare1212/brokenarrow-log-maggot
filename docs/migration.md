# JSON → SQLite

用户目录仍为 broken-arrow-log-assistant，新库 assistant.sqlite。迁移不运行旧构造器、不改旧 JSON。

旧版请求用量文件不再导入，原文件保留。打开已有 SQLite 时会移除停用的请求计数表和累计计数。

| 来源               | 内容                                                       |
| ------------------ | ---------------------------------------------------------- |
| settings.json      | 设置、主题 / 语言 / 排序、录像参数；私有请求头仅服务端保留 |
| players-db.json    | v1 / v2 玩家、名字、对局、账号、封禁、快照、原 encounters  |
| match-archive.json | 同 FID 补缺，无 FID 保留稳定内部 ID                        |
| batrace-cache.json | 原 key、时间、payload、各命名空间 TTL                      |
| deck-sync.json     | 上一局包归属与提醒状态                                     |
| api-health.json    | 上次探测                                                   |

1. 验证来源；损坏格式保留诊断，不记录为成功。
2. 已读取 bytes 独占写入 migration-backups；不同快照用哈希后缀，不覆盖。
3. 单事务导入有效来源、原 JSON 和 SHA-256，完成后记录标记；失败回滚。
4. 后续跳过成功来源，仅重试失败来源。未知字段保存在 legacy_imports 和备份。

导入不套用运行时缓存 / 快照淘汰。archive 只补缺，不降低已有 API 名单和指标；0 / false / null 分开，旧毫秒时间不再乘 1000。

v1 原 encounters 与数字 FID 聚合同时保留；不能证明归属时不全部指定给最近账号。无 FID、未知所有权仍保留。缺玩家允许占位，但不据此声称相遇。

对局、名单、账号视角分表。删除保护其他已知账号和视角，不递归删游戏目录。录像保持原位置；用户明确迁移时才移动，目标已有同名文件不覆盖。

专项测试核对原字节、格式错误、备份冲突、读后源变化、事务失败、v1 / v2、改名、同 / 无 FID、0 / false、超过 2000 条缓存、幂等启动。
